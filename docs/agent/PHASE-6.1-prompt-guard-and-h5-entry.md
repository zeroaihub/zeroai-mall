# Phase 6.1 — 事实约束加固 + H5 AI 导购入口

- **日期**：2026-10-27
- **前置**：Phase 6（提议 + 确认）已通过
- **本阶段性质**：缺陷修复 + 前端入口补齐，不动交易链路

---

## 1. 背景：一个真实回答质量问题

Phase 6 联调时问「查一下我的订单」，模型只调了 `list_my_orders`，却在结尾补了一句
「购物车里正好有 2 件已勾选」。查库实际有效购物车 `del_flag=0` 为 **0 件**
（DB 里那两行 `del_flag=1` 是软删记录），属于**无工具依据的事实编造**。

同类风险：价格、库存、订单状态都是会变的业务事实，模型凭上下文"顺手断言"比完全编造更隐蔽。

## 2. 改动

### 2.1 提示词（`prompts/mall-agent-system.st`）

新增两节硬约束：

| 小节 | 约束 |
|---|---|
| 关于事实依据 | 本轮没调过的工具就等于"不知道"；不得断言购物车件数 / 订单状态 / 价格 / 库存 / 地址；工具报错或空结果时不得用"通常……""一般……"补全结论；同会话重复提问必须重新查（价格库存会变），且不要说"我已经查过 N 次" |
| 输出格式 | 移动端气泡只渲染纯文本，禁用 `**` 加粗、`#` 标题、`|` 表格、代码块；列举用「- 」短行，订单信息压成单行 |

> 为什么用提示词而不是前端渲染 Markdown：`v-html` 渲染模型输出会引入 XSS 面；
> 纯文本 + `white-space: pre-wrap` 是最小风险的方案，格式问题在生成侧约束。

### 2.2 H5 端 AI 导购入口（`web/zeroai-mobile`）

| 文件 | 说明 |
|---|---|
| `src/views/ai/index.vue` | 对话页：欢迎态 + 示例问题、气泡列表、工具过程态 chips、输入栏、停止/清空 |
| `src/api/ai.js` | `streamAgentChat()`：`fetch` + `ReadableStream` 手动解析 SSE，携带 `Authorization` |
| `src/components/AiEntry/index.vue` | 主页面右下角浮动入口，位于 tabbar 之上 |
| `src/router/index.js` | 新增 `/ai`（`AiAssistant`），声明在兜底路由 `/:pathMatch(.*)*` 之前 |
| `src/App.vue` | 在 `meta.showTab` 页面渲染 `<ai-entry />` |

**为什么不用 `EventSource`**：`/ai/**` 需要登录态，而 `EventSource` 不能自定义请求头，
只能退化成把 token 放 query（会进日志、进浏览器历史），因此改用 `fetch` 手动消费流。

## 4. 已知限制

1. 提示词是软约束，不能 100% 杜绝编造；真正的防线是"工具出参白名单 + 写操作只能由确认接口执行"。
2. 会话按用户持久化在 `.agentscope/workspace/u{userId}`，不同问题会带上前文语境（如「又查了一遍」）。
3. 前端不渲染 Markdown；若后续要展示商品卡片，应走 `product_cards` 事件的结构化数据，而不是解析文本。
